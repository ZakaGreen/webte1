# Как устроено задание

## Путь от HTML до приложения

`index.html` содержит пустой блок `#app` и подключает `main.js`.
`createApp(App).mount('#app')` помещает главный компонент в этот блок.
Vite нужен для запуска разработки и сборки файлов `.vue` в обычный JS.

## Кто хранит задачи

В `App.vue` находится `tasks = ref([])`. Это массив, за изменениями которого
следит Vue. В JavaScript значение читается через `tasks.value`, а в шаблоне
достаточно `tasks`. Сервер является постоянным хранилищем; массив содержит
последнюю загруженную копию данных для отображения.

`TaskList` и `TaskCalendar` получают один массив через props. Они не меняют
его напрямую. Например, кнопка удаления в списке вызывает emit('remove', task).
Главный компонент получает событие и отправляет DELETE.

## Как работает запрос

`api.js` собирает URL, кодирует имя, задаёт HTTP-метод и при необходимости
преобразует объект в JSON. Fetch не считает HTTP 403 или 500 сетевой ошибкой,
поэтому отдельно проверяем response.ok. DELETE возвращает 204 без тела:
для такого ответа нельзя вызывать response.json().

GET списка возвращает объект студента с массивом todos. GET одной задачи
используется при открытии подробностей из календаря.

В App.vue функция change получает действие и текст успеха. Сначала ждёт
запрос изменения, потом загружает общий список. Во время запроса busy
блокирует повторную отправку. finally снимает блокировку и при ошибке.
Если изменение прошло, но повторное чтение не удалось, сообщение отдельно
говорит, что изменение сохранено: повторять создание задачи не требуется.

## Форма

TaskForm копирует значения задачи в отдельный объект form. Поэтому ввод
пока не меняет список. Проверяются пустой или слишком длинный заголовок,
длина описания, даты и порядок начала/конца. Ошибки находятся возле полей.
При успехе emit('save', ...) отправляет данные родителю. Родитель выбирает
POST для новой задачи или PUT при наличии id. PUT отправляет все пять полей.
При ошибке запросов форма остаётся открытой с введёнными значениями.

## Фильтры и календарь

computed пересчитывается, когда меняются используемые данные. В списке
filter выбирает подходящие задачи, затем копия массива сортируется по дате.
Исходный порядок tasks не изменяется. В календаре computed строит массив
дней выбранного месяца, недели или дня. Для месяца сетка начинается
с понедельника и заканчивается воскресеньем. В неделе и дне задачи
отображаются списком внутри соответствующих дат.

Функция tasksForDay выбирает задачи, пересекающие данный день. Многодневная
задача отображается в каждом затронутом дне. taskTime показывает часть её
интервала за этот день, например 00:00–24:00 для полного промежуточного дня.
При клике по дате функция select отправляет родителю интервал 09:00–10:00.
Родитель открывает ту же форму. Отдельной библиотеки календаря нет.

## Даты и текст

datetime-local содержит местное время без часового пояса. При отправке
new Date(...) и toISOString() преобразуют его в UTC с суффиксом Z.
Для формы toInputDate собирает местные компоненты даты; для чтения
используется toLocaleString('sk-SK'). Календарь также использует местные даты; дни сдвигаются через setDate,
а не прибавлением 24 часов, чтобы учитывать переходы на летнее время.

Интерполяция {{ task.title }} выводит текст. В проекте нет v-html для
данных сервера: название с HTML-тегами не выполняет код.

## Что стоит объяснить на защите

1. Чем ref отличается от обычного массива и зачем computed.
2. Как props и emit связывают родителя и дочерний компонент.
3. Чем POST, PUT, PATCH и DELETE отличаются в этом API.
4. Зачем два await: для fetch и для чтения JSON.
5. Почему после изменения перечитываются данные.
6. Зачем форма редактирует копию и как работают проверки.
7. Как местное время преобразуется в UTC и обратно.
8. Как строится сетка календаря и выбираются задачи каждого дня.

## Атрибуты и зависимости

Оставлены Vue, Vite и плагин Vue для сборки. Vue обязателен по заданию,
Vite преобразует компоненты .vue в обычные файлы для школьского сервера.
Запросы, даты и календарь используют встроенные возможности JavaScript.

Убраны дополнительные ARIA-атрибуты и role. Атрибуты type, disabled,
maxlength, step и Vue-директивы сохранены там, где управляют поведением.
for связывает подпись с полем, а tabindex на заголовке подробностей
позволяет перенести туда фокус. Проверки формы выполняются в submit;
novalidate отключает встроенные всплывающие сообщения браузера.
